# Taste
- Communicates in Vietnamese and expects replies in Vietnamese (including status summaries and end-of-day recaps). Confidence: 0.92
- Rejects UI that looks foreign to the existing app: new controls must reuse the current design tokens (colors, 11.5px sizing, border radius, spacing) and visually match the neighbouring buttons/controls (same height, border, background, hover/focus states, custom chevron instead of the OS default arrow) instead of adopting another palette; misaligned/oversized controls are called out as "lạc quẻ". Alignment is judged at the pixel level: a badge/pill whose dot or label sits even a few pixels off the vertical centre gets re-reported ("chữ … lại bị lệch"), so inner elements should be measured and centred explicitly rather than eyeballed via screenshots. Confidence: 0.85
- Directs visual redesigns by attaching a reference screenshot/image and expects the implementation to follow that reference's layout closely (e.g. pill-style tabs, rounded search field with icon, collapsible groups, rounded value boxes). Confidence: 0.7
- For small top-bar choices prefers a compact dropdown select (styled like the app's existing dropdowns) over a row of segmented buttons, which he asks to be replaced because the dropdown looks cleaner. Confidence: 0.5
- Likes soft, rounded, modern component styling (10px rounded containers, 8px rows, subtle shadows, hover/focus rings) applied within the app's existing tokens rather than default browser controls. Confidence: 0.65
- Wants long-running agent work to show visible, staged progress in the main workspace — which step is active, what the agent is doing right now, elapsed time — plus a way to cancel mid-run; the status must also make server/connection liveness obvious (alive vs. silent vs. API down) so a long wait is never wasted on a dead backend, since he resents finding out after ~10 minutes that the server was never connected, and a render that sits at "đang chờ" for many minutes gets reported back as a screenshot with "sao N phút chưa dựng được hình" rather than being tolerated. Confidence: 0.88
- Prefers the generated result to appear progressively (parts growing in one by one like a build animation) rather than snapping into view complete, for a livelier feel — he asks for it explicitly even after a partial version exists ("dựng xong part 1 đưa hình ra cho user xem… dần dần hình thành nhìn rất đẹp"); and debug/helper overlays he asks for (e.g. Revit-style green reference planes) should be toggleable. Confidence: 0.8
- Prefers the local Command Code CLI (`cmdc`) as the agent backend, with a model selector, rather than API-key providers such as OpenAI. Confidence: 0.7
- Wants the workspace layout adjustable by the user: both the left (agent/chat) panel and the right (parameters/parts) panel must be draggable wider/narrower instead of occupying fixed widths. Confidence: 0.6
- Wants tools to accept real project documents (e.g. a manufacturer PDF datasheet) and take dimensions/components from them, not just free-text descriptions. Confidence: 0.6
- Judges generated Revit families by whether they are actually editable in Revit: geometry must be native parametric family forms (Extrusion / Void extrusion, Blend, Revolve, Sweep) whose faces are locked to reference planes and whose planes carry labelled dimensions, not FreeFormElement solids with loose parameters — anything that does not visibly move when a parameter changes in Revit is rejected as unusable compared with professional families (e.g. new.family). Confidence: 0.78
- Judges generated geometry by physical/constructive logic, not just dimensions and valid schema: component placement must be plausible in reality (e.g. the condensate drain pan must sit under the cooling coil, the filter before the coil, the fan matched to the outlet, no part floating outside the casing) and he asks for accuracy in both shape and logic to be improved. Confidence: 0.65
- Expects constraints to work in both directions — editing a length/width parameter must drive the geometry, and moving geometry in Revit must feed back into the parameter — not just a one-way dimension label; likewise every dependent part must follow (doors, back panel, internal bays), so sizes derived from another dimension belong in formulas referencing it instead of hard-coded numbers — a widened cabinet whose doors stay put is reported as a bug. Confidence: 0.82
- Dislikes hard-coded fixed settings and asks for them to become user-facing choices instead (e.g. a detail/LOD level selector rather than one baked-in standard), with the whole pipeline actually honouring the chosen value. Confidence: 0.6
- Wants the dev/preview server left running after changes are finished so he can test manually right away — shutting it down and cleaning up is a mistake, not thoroughness. Confidence: 0.65
- Prefers the assistant to finish all remaining proposed work in the same go rather than stopping to present a menu of follow-up options for approval ("còn gì nữa không bạn làm nốt đi") — report what is still outstanding at the end, then do it. Confidence: 0.6
- Wants `main` treated as off-limits: a push must go only to the branch currently being worked on (e.g. `UI-Theme`), never to `main`, and stale `main` content must not be folded into a branch as a side effect. Before every commit/push he expects the current branch to be checked explicitly — switching to the right branch first if standing on `main` — and the push command to name the branch explicitly. If a commit lands on `main` by mistake, it must be moved to the branch (cherry-pick) and `main` reset back to `origin/main`; branch state should be verified and reported back. Confidence: 0.9
- Wants git pushes to GitHub to be explicit-only: don't push after each change, local commits are acceptable when needed, but pushing must wait for his instruction. Confidence: 0.85
- For chat input attachments, wants compact image chips (thumbnail + size + remove) without the raw file name shown (name only in tooltip), and the attachment row must not squeeze the textarea or push the attach/send buttons around — the composer has to stay full-width and comfortable to type in. Confidence: 0.6
- Prefers one-click end-to-end execution: a build action must hand back the final artifact (e.g. the .rfa file) itself, auto-launching whatever external app is needed, instead of telling him to open Revit manually or settle for a queued/manual finish. Confidence: 0.6
