# Taste
- Communicates in Vietnamese and expects replies in Vietnamese (including status summaries and end-of-day recaps). This extends to the product's own text: user-facing strings — UI labels, stage/status hints, server and error messages — must be Vietnamese too, not English ("Việt hoá toàn bộ chuỗi"; error messages requested "bằng tiếng Việt"). Confidence: 0.92
- Insists failures be reported with the true cause, never silently or generically: a step that dies must not just stop the pipeline ("không được dừng im lặng"), the final error has to name the real reason per step (plus a `detail` for the details block), and distinct failure modes must be separated into their own codes/messages instead of being lumped into one path (a CLI turn cap "Reached maximum conversation turns" is not an output-token cap and must not be classified as one, since the two need different fixes). Messages must also match what actually happened — never wording a kept/failed run as a successful update. When he reports a bug with real logs, he expects durable diagnostics to be added as part of the fix: one log line per model call with model, prompt size, elapsed time and the end reason (ok/timeout/max_turns/output_limit/error/cancelled). Confidence: 0.7
- Rejects UI that looks foreign to the existing app: new controls must reuse the current design tokens (colors, 11.5px sizing, border radius, spacing) and visually match the neighbouring buttons/controls (same height, border, background, hover/focus states, custom chevron instead of the OS default arrow) instead of adopting another palette (ad-hoc inline styles from another contribution get flagged with "chỉnh lại cho đồng bộ với dự án" and should be refactored into named CSS classes/variables — new styling belongs in `styles.css` as named classes on the existing colour variables, never inline `style={}`, and must keep enough contrast in both the light and the dark theme); misaligned/oversized controls are called out as "lạc quẻ". Consistency also means reusing the app's existing shared control markup/CSS instead of a bespoke one-off class: a new filter/search field gets "đồng bộ … cho giống ô bên parameter", so it must reuse the same `.filter` wrapper, icon, placeholder style and placement as its sibling panel, and the custom class is deleted. Alignment is judged at the pixel level: a badge/pill whose dot or label sits even a few pixels off the vertical centre gets re-reported ("chữ … lại bị lệch"), so inner elements should be measured and centred explicitly rather than eyeballed via screenshots.
